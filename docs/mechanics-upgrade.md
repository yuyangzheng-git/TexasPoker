# 牌局机制改进说明

本次修改针对实际复现的问题，覆盖下注规则、信息可见性、连接恢复及账户兼容性。

## 下注与结算

- 非法行动先拒绝，不扣筹码、不写入历史，也不会把人类玩家的非法过牌自动改成付费跟注。
- 仅轮到的玩家可以行动；一次行动结束后，从下一座位开始寻找仍需行动的玩家。
- 加注金额统一表示本轮累计下注到多少（raise-to），前端使用后端给出的最小值与最大值。
- 最小再加注按上一次完整加注的增量计算。例如从 20 加到 100，下一次至少加到 180。
- 短筹码只能用全押投入剩余筹码，不能把桌面最高下注额调低。
- 不足完整增量的全押不会直接恢复已行动玩家的加注权限；多个短全押累计达到完整增量时才恢复。
- 双人局庄家付小盲，翻牌前先行动、翻牌后后行动；后续牌局会跳过淘汰座位。
- 对手全部全押后，不再要求唯一仍有筹码、且已覆盖对手下注的玩家额外下注。
- 同一手结算只执行一次；赢得多个边池的玩家只返回一条汇总结果。

加注和重新开放下注的原则核对了 [Poker TDA 官方规则](https://www.pokertda.com/view-poker-tda-rules/)。本项目仍是模拟平台，并未实现完整的线下赛事规则体系。

## 底牌与 AI 思考

服务器只向玩家发送自己的底牌。摊牌时才发送仍在局内的对手底牌，弃牌者的底牌保持隐藏。

AI 的内部思考可能包含底牌，因此不再在下注期间传到浏览器；本手结束后再展示。角色发言仍属于公开信息。包含完整底牌和思考的日志接口改为仅管理员可访问。

## 会话与重连

创建牌局会得到一个随机 `sessionToken`，前端保存在当前浏览器标签页的 `sessionStorage` 中。它是这张牌桌的访问凭证，请勿分享。

- WebSocket 首条消息必须提交该凭证，凭证不放在连接 URL 中。
- 一张牌桌只有一个游戏任务，同一时刻只接受一个连接。第二个连接会被拒绝。
- 连接中断后自动尝试重连，恢复当前手牌、筹码、待操作请求、剩余时间或结算结果，不重新发牌或扣盲注。
- 每次行动及下一手确认使用独立 `requestId`，过期请求不会被当成下一轮操作。
- 人类玩家超时后，有欠注则弃牌，无欠注则过牌；浏览器不再重复提交超时弃牌。
- 暂停在当前行动结束后生效。已开始的人类行动仍按原时限处理，断线也不会重置时限。
- 断开连接且 30 分钟无活动的牌局会清理。

当前会话保存在单个后端进程内。请使用一个后端 worker；服务重启会丢失牌局。跨进程或重启恢复需要后续加入共享会话存储及持久化事件记录。

## 账户与部署

新密码使用 scrypt，支持长 Unicode 密码；旧 bcrypt 密码记录仍可验证，无需重置已有账户。

环境配置在初始化数据库、登录模块及 AI 客户端之前加载。生产环境设置 `APP_ENV=production`，并配置私有、随机、至少 32 字符的 `JWT_SECRET_KEY`。生产模式拒绝缺失、过短或项目旧版公开密钥。开发模式缺少密钥时使用进程临时密钥，重启后需重新登录。

前端统一使用 `src/config.ts` 的接口地址。开发环境默认访问本机 8000 端口；生产环境默认同源，HTTPS 页面使用 WSS。独立 API 主机可以在构建前设置 `REACT_APP_API_URL=https://api.example.com`，后端 `FRONTEND_URL` 配置允许的前端来源，多个来源用逗号分隔。

同源部署需要反向代理 `/api/` 和 `/ws/` 到后端，并为 `/ws/` 转发 WebSocket Upgrade；其他路径返回前端静态文件，前端路由回退到 `index.html`。

## 验证方法

后端：

```sh
python3 -m venv backend/venv
backend/venv/bin/pip install -r backend/requirements.txt pytest
backend/venv/bin/python -m pytest tests -q
```

前端：

```sh
cd frontend
npm ci
npm test -- --watchAll=false --runInBand
npm run build
```

前端保留现有 CRA 5 构建体系，`.npmrc` 记录了与 TypeScript 5 配套安装所需的 peer-dependency 兼容设置。

测试覆盖完整对局、多个边池、80 组不同人数及筹码的随机对局守恒、短全押、行动顺序、超时、非法指令、重连、重复连接、前端凭证与操作编号，以及真实注册和登录接口。AI 调用在会话测试中替换为确定性测试代理，不产生付费 API 请求。

本次本地验证：83 项后端测试、5 项前端测试通过，生产构建成功（仍有原有大厅及管理页面的 Hook 依赖提示）。另以两个随机种子完成了共 40 手 MC / random 基准对局，并校验双方策略覆盖六种位置。这些验证不替代真实 LLM 服务联调或完整浏览器验收。
